# Runbook: сайт или админка «сломались»

Краткие шаги для продакшена IQMO (статика + Node или Laravel + MySQL).

## 1. Сайт отдаёт 502 / не открывается

- Проверить, что **процесс** жив: Node (`pm2`, systemd) или PHP-FPM + nginx.
- Проверить **логи** приложения и nginx (`error.log`).
- Проверить **диск** и **права** на каталог со статикой.

## 2. Не работает вход / «unauthorized» на API

- Открыт ли сайт по **HTTPS/HTTP с того же хоста**, что и API (cookie `iqmo_session` привязана к домену и `Path=/`).
- Задан ли **`IQMO_JWT_SECRET`** и совпадает ли он между инстансами.
- Жива ли **MySQL**: `users`, `profile_state`.

## 3. Не сохраняется прогресс (синхронизация профиля)

- Ответ `409 revision_mismatch` — нормальная гонка; клиент должен подтянуть серверное состояние.
- Проверить `PUT /api/profile/state` в логах и размер `keys_json`.

## 4. Аналитика не пишется в БД

- Пользователь **должен быть залогинен** (ингест с `auth` на Node и JWT на Laravel).
- Проверить **429** — слишком частые батчи; лимит настраивается `IQMO_ANALYTICS_RATE_PER_MIN` (Node).
- Убедиться, что таблица **`analytics_events`** существует и миграции применены.

## 5. Админка

- Проверить allowlist / middleware портала (email, сессия).
- Убедиться, что отдаётся актуальный **`admin-ui`** или защищённый маршрут, а не устаревший файл из кэша CDN.

## 6. Бэкапы MySQL

Рекомендуется ежедневный **дамп** базы `iqmo` (или общей БД портала):

```bash
mysqldump -u USER -p --single-transaction iqmo > iqmo-$(date +%F).sql
```

Хранить вне сервера (S3, отдельный бэкап-хост). Перед восстановлением — остановить записывающие сервисы или переключить в read-only.

## Контакты и эскалация

Зафиксируйте внутри команды: ответственный за DNS, сервер, БД и доступ к кабинету Метрики.
