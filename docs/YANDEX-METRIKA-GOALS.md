# Цели в Яндекс.Метрике для IQMO

Этот документ — однократная инструкция по настройке целей в кабинете
Яндекс.Метрики, чтобы оживить вторую (независимую от нашей админки) воронку
по тем же событиям, которые фронт уже отправляет.

- **Счётчик IQMO**: `108770166`
- **Кабинет Метрики**: <https://metrika.yandex.ru/list>
- **Ecommerce-источник в инициализации**: `dataLayer` (см. `extracted/index.html:13`
  и парный `<script>` на каждой странице)
- **Где живёт код**: все цели вызываются из фронт-кода в `extracted/` (источник
  правды) и `laravel/public/site/` (то, что отдаёт прод).

> Создание цели в кабинете занимает ~30 секунд: «Настройка → Цели → Добавить
> цель → JavaScript-событие → ввести идентификатор». Идентификатор — это и
> есть тот короткий ключ, который мы передаём как 3-й аргумент `ym(... 'reachGoal',
> '<id>')`. Все наши цели — типа JavaScript-событие, кроме двух Ecommerce-целей,
> для которых дополнительно нужно один раз включить раздел «Электронная коммерция»
> в настройках счётчика (если ещё не включён).

## Сводный чек-лист

Создайте в кабинете эти 6 целей. Колонка **Тип** = JS-event для всех.

| # | Идентификатор    | Название в кабинете (рекомендация)         | Тип    | Триггер (когда срабатывает)                              |
| - | ---------------- | ------------------------------------------ | ------ | -------------------------------------------------------- |
| 1 | `login`          | Вход в кабинет                             | JS     | Успешный логин (`POST /api/auth/login` ответил 2xx)      |
| 2 | `register`       | Регистрация                                | JS     | Успешная регистрация (`POST /api/auth/register` 2xx)     |
| 3 | `topic_view`     | Просмотр темы                              | JS     | Открыт любой `/topic-*.html` (первый раз за сессию)      |
| 4 | `test_complete`  | Завершение теста                           | JS     | Пользователь дошёл до итогов теста (любой режим)         |
| 5 | `begin_checkout` | Начало оплаты                              | JS     | Клик «Оплатить» на `/uploads/payment.html`               |
| 6 | `purchase`       | Оплата завершена                           | JS     | Открыта `/uploads/thank.html` (постоплата, 1 раз/день)   |

После создания всех шести цели начнут собирать данные **в течение 1 часа**
(Метрика обычно догоняет за 10–30 минут). Затем в кабинете будут доступны:
конверсии, сегменты, отчёт «Конверсии по целям», построение собственной
воронки в «Аналитике».

## Как создать одну цель (на примере `login`)

1. Кабинет → выбираем счётчик `IQMO (108770166)`.
2. Слева **«Настройка» → «Цели»**.
3. Кнопка **«Добавить цель»**.
4. Поле **«Название»**: «Вход в кабинет».
5. **«Тип условия»**: `JavaScript-событие`.
6. **«Идентификатор цели»**: `login` (ровно так, без префиксов и пробелов).
7. **«Сохранить»**.

Повторите для остальных пяти строк из таблицы выше — поля «Идентификатор»
менять на соответствующее значение из колонки «Идентификатор», «Название» —
на текст из колонки «Название».

> ⚠️ Имя цели **чувствительно к регистру**. Идентификатор `Login` не равен
> `login`. Если опечатались — Метрика просто не будет ловить событие, без
> явной ошибки.

## Подробно по каждой цели

### 1. `login` — успешный вход

**Где выстреливает:** [`extracted/login.html:381`](../extracted/login.html#L381),
[`extracted/uploads/login.html:368`](../extracted/uploads/login.html#L368)

```js
window.dataLayer.push({ event: 'iqmo_login' });
if (typeof ym === 'function') ym(108770166, 'reachGoal', 'login');
```

Срабатывает **только** если `/api/auth/login` ответил 2xx. На ошибочных
паролях/email НЕ выстрелит — это правильно, в кабинете не будет «фейковых»
конверсий.

### 2. `register` — успешная регистрация

**Где выстреливает:** [`extracted/login.html:426`](../extracted/login.html#L426),
[`extracted/uploads/login.html:413`](../extracted/uploads/login.html#L413)

```js
window.dataLayer.push({ event: 'iqmo_register' });
if (typeof ym === 'function') ym(108770166, 'reachGoal', 'register');
```

Срабатывает только при HTTP 2xx от `/api/auth/register`.

### 3. `topic_view` — просмотр темы

**Где выстреливает:** [`extracted/chem-progress.js:867`](../extracted/chem-progress.js#L867)

```js
reachMetrikaGoal('topic_view', { topicSlug: String(slug) });
```

Срабатывает на `DOMContentLoaded` любой страницы с `data-iqmo-topic`
(`topic-periodic-table.html`, `topic-chemical-bond.html`, … — всего 10 тем).
Дедуп по `sessionStorage`: одна тема — одна цель за сессию.

В Метрику попадает с параметром `topicSlug` (например `periodic-table`).
В отчёте «Цели» можно отфильтровать по топику через сегмент.

### 4. `test_complete` — завершение теста

**Где выстреливает:** [`extracted/chem-progress.js:810`](../extracted/chem-progress.js#L810)

```js
reachMetrikaGoal('test_complete', {
    mode: String(payload.mode),     // warmup | quick | trial | full
    percent: payload.percent,       // 0..100
    subject: String(payload.subject) // 'chemistry'
});
```

Срабатывает в `recordAttempt()` — то есть когда фронт получил итог теста
(независимо от результата: 0 % это тоже «завершение»). Параметры доступны
в Метрике через сегмент «Параметры цели».

### 5. `begin_checkout` — начало оплаты

**Где выстреливает:** [`extracted/uploads/payment.html:391`](../extracted/uploads/payment.html#L391)

```js
window.dataLayer.push({ event: 'begin_checkout', ecommerce: { /* … */ } });
if (typeof ym === 'function') ym(108770166, 'reachGoal', 'begin_checkout');
```

Срабатывает при сабмите формы оплаты. Дедуп по `sessionStorage` — одна
сессия = одна цель (повторные клики не учитываются).

### 6. `purchase` — оплата завершена

**Где выстреливает:** [`extracted/uploads/thank.html:105`](../extracted/uploads/thank.html#L105)

```js
window.dataLayer.push({ event: 'purchase', ecommerce: { /* full GA4 shape */ } });
if (typeof ym === 'function') ym(108770166, 'reachGoal', 'purchase');
```

Срабатывает на загрузке `/uploads/thank.html`. Дедуп по дню (`day-key`):
если пользователь открыл «спасибо» дважды за сутки — конверсия учтётся один
раз. Это сделано чтобы избежать накрутки при F5 на странице.

## Электронная коммерция: дополнительный шаг

Цели `begin_checkout` и `purchase` дублируют клик с пушем в `dataLayer`.
Метрика умеет читать ecommerce из dataLayer и строить отчёт **«Электронная
коммерция»** (выручка, средний чек, воронка checkout) — но для этого нужно
один раз включить опцию в настройках счётчика:

1. Кабинет → счётчик `IQMO` → **«Настройка» → «Счётчик»** (вкладка с кодом).
2. Раскрыть секцию **«Дополнительно»**.
3. Включить **«Электронная коммерция»**, в поле «Контейнер данных» оставить
   **`dataLayer`** (это то самое имя, которое у нас в `ym(... 'init', { ecommerce: "dataLayer" })`).
4. Сохранить.

После этого в **«Отчёты → Электронная коммерция»** появится воронка
checkout, средний чек, ARPU. Это пойдёт **только** с момента включения опции,
исторические данные не подтянутся — но это нормально.

## Как проверить, что цель ловится

После создания целей зайдите на прод (или локально на `http://localhost:3780/`)
и посмотрите в DevTools → Network → фильтр `mc.yandex.ru/watch/`. На каждое
событие должен лететь `goal/<id>` запрос. Если запросы есть — цель работает.

Альтернатива в браузере — режим отладки Метрики:

```
https://iqmoschool.ru/?_ym_debug=1
```

`_ym_debug=1` включит подробный лог в DevTools Console: будет видно каждый
`reachGoal` с именем и параметрами. Удобно для проверки `topic_view` и
`test_complete` (просто пройдите путь и убедитесь, что в консоли нужная цель
выстрелила).

## Связь с нашей собственной аналитикой

Эти 6 целей в Метрике — **верхний слой** наблюдаемости. Параллельно мы пишем
свои события в MySQL `analytics_events`:

| Метрика-цель      | Наш event (в `analytics_events`)         | Источник     |
| ----------------- | ---------------------------------------- | ------------ |
| `topic_view`      | `chem.topic_view`                        | `chem-progress.js:858` |
| (нет аналога)     | `chem.attempt_start`                     | `chem-progress.js:174` |
| `test_complete`   | `chem.attempt_complete`                  | `chem-progress.js:771` |

Текущий whitelist на стороне бэкенда — три события, см. `AnalyticsIngestController::ALLOWED_EVENTS`.
Цели Метрики `login`/`register`/`begin_checkout`/`purchase` параллельных
записей в MySQL не имеют — это маркетинговая часть, авторизация и оплата
видны в Метрике, но не пишутся в нашу `analytics_events` (и это правильно:
они происходят и так в auth/payment-эндпоинтах, дублирование не нужно).

Воронка из MySQL рисуется в нашей админке (`/admin/index.html`) и в
event-funnel-блоке. Воронка в Метрике строится по тем же шагам, но видна
только маркетингу (без авторизации в IQMO). Когда обе воронки сходятся по
порядкам — это дополнительный sanity-check, что ингест работает.

## Замечания по эксплуатации

- **Удалять цели нельзя «лёгким» способом**: после удаления цели её
  идентификатор недоступен ~3 дня. Если опечатались — лучше переименуйте
  «Название», а идентификатор оставьте.
- **Лимит**: до **200 целей на счётчик** (нам с этим жить ещё долго).
- **При смене counter id** (если когда-нибудь решим завести второй счётчик)
  все 6 целей придётся пересоздать в новом — Метрика их не клонирует.
  Идентификатор `IQMO_METRIKA_ID` в `chem-progress.js:6` и хардкод
  `108770166` в HTML на каждой странице — единое место правды; меняется
  одной заменой.
- Если на странице **нет блока инициализации Метрики** (его не должно
  быть, но проверьте — наш smoke-тест `deploy.yml` ловит регрессию для
  `/subject-chemistry/`), `reachGoal` тихо ничего не делает
  (`typeof ym === 'function'` ложно). Никакой ошибки в консоли не будет.
